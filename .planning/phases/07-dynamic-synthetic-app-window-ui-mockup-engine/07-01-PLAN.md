<objective>
Build the adaptive device classification and metadata pipeline that decides whether the app window renders in macOS Chrome (landscape desktop browser) or Mobile Phone (portrait smartphone) framing based on prompt keyword semantics and uploaded photo dimensions/aspect ratio.

Purpose: Guarantee that every launch video frames the product natively (desktop SaaS vs mobile app) without requiring manual configuration, while offering effortless manual override.
Output: Server and client device classifiers, image dimension detection, storyboard schema integration, StoryboardInspector UI controls, and automated test suite.
</objective>

       - Mobile indicators: `ios`, `iphone`, `ipad`, `android`, `mobile app`, `phone app`, `app store`, `play store`, `pocket`, `on your phone`, `swipe`, `tap to`, `push notification`, `mobile-first`, `handheld`.
       - Desktop/SaaS indicators: `saas`, `dashboard`, `web app`, `website`, `chrome`, `browser`, `desktop`, `laptop`, `macos`, `mac`, `windows`, `portal`, `admin panel`, `cloud console`, `analytics dashboard`, `crm`, `b2b`, `platform`.
    2. Define `classifyDeviceFrame({ prompt, imageDimensions, override })`:
       - If `override` is 'macos' or 'mobile', return override.
       - If `imageDimensions` provided (width, height):
         - If ratio (width / height) < 0.95 -> 'mobile' (phone screenshot).
         - If ratio (width / height) > 1.05 -> 'macos' (desktop / laptop screenshot).
       - Analyze prompt text:
         - Count mobile keyword occurrences vs desktop keyword occurrences.
         - If mobileCount > desktopCount -> 'mobile'.
         - Else default to 'macos'.
    3. Create comprehensive tests in `tests/deviceClassifier.test.js` verifying mobile prompts, desktop prompts, portrait screenshots, and landscape screenshots.
  </instruction>
